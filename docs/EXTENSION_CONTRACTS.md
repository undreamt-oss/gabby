# Extension contracts

This page describes the extension interfaces re-exported by `gabby`. It is a reference for the
current `0.x` implementation, not a compatibility guarantee. Public extension APIs may change before
`1.0`; see the [extension API policy](EXTENSIONS.md) and [ADR 0009](architecture/adr/0009-pre-1-0-extension-api-policy.md).
The v1.0 supported set and the release maintenance window are defined by
[the compatibility policy](COMPATIBILITY.md) and [ADR 0064](architecture/adr/0064-v1-compatibility-and-deprecation-policy.md).

Unless a row says otherwise, an injected implementation is owned and closed by the host that created
it. Gabby does not close host-injected providers, stores, callbacks, or adapters. Implementations
must not assume one global call at a time: separate agent runs can invoke a shared extension
concurrently. Protect mutable state or create request-scoped objects when needed.

## Extension matrix

| Interface | Required operation | Result contract | Execution and failure behavior |
|---|---|---|---|
| `Environment` | `Environment(..., tools=..., resources=..., allowed_tools=...)` | Describe the operating context, declared capabilities, registered tools, scoped host resources, and optional tool allowlist. The resolved environment snapshots declarations and binds an agent-local frozen tool registry. | Resource handles remain host-owned references and are never serialized into model context. Tools receive only resources named in their `context_resources` grant. The host owns resource lifecycle and must keep shared handles safe for concurrent runs. |
| `PolicyEngineFactory` / `PolicyEngineProtocol` | `async create(*, declared_tools, policies, environment_allowed, principal)`; async `authorize_tool(name)` and `authorize_permissions(name, permissions)` | Return a run-scoped policy engine that decides whether each active tool and its permissions are allowed. The built-in `PolicyEngine` and `DefaultPolicyEngineFactory` implement the default allowlist and permission checks. | The runtime creates the engine after skill activation and awaits authorization within the run deadline before exposing tools to the model. Policy denials and implementation failures are sanitized. A custom factory is trusted host code and must fail closed; the host owns its lifecycle and must support concurrent calls across runs. |
| `Tool` | `Tool(..., parallel_safe=False)` | A tool marked parallel-safe explicitly declares that independent invocations of its host handler may overlap. | Defaults to sequential calls. The runtime concurrently dispatches a model tool batch only when every referenced tool is registered, host-trusted, unapproved, and marked parallel-safe; `policies.max_parallel_tool_calls` bounds each concurrent batch to at most 32. Tracer-enabled runs remain sequential to preserve ordered trace delivery. |
| `AgentTool` | `AgentTool(child_agent, *, name, description).to_tool()` | Produce a parent `Tool` whose JSON input contains one explicit child task and whose result contains the child agent name, output, and trace ID. The child trace records `parent_trace_id` in its metadata and request event. | Child calls are async, bounded by the parent tool timeout and input/result byte caps, and limited to eight nested agents with cycle detection. The child receives no parent context, memory, metadata, or principal by default; principal forwarding is opt-in. The host owns both agents and closes both. |
| `ModelProvider` | `async complete(*, messages, tools, model, temperature, timeout_seconds)` | Return a `ModelResponse` with assistant text and/or structured tool calls. Tool calls must preserve provider IDs, names, and JSON arguments. Optional `provider_metadata` on a call may carry bounded JSON state required for a provider-specific multi-turn tool cycle. | Honor the supplied timeout. The runtime passes provider metadata back in the corresponding assistant tool call and does not expose it in traces or tool arguments. Keep it JSON-compatible, bounded, and safe to send only to the originating provider. Raise `RetryableModelError` only for transient failures safe to retry; redact secrets and enforce response caps while reading. |
| `StreamingModelProvider` | `stream(*, messages, tools, model, temperature, timeout_seconds)` | Yield `ModelStreamDelta` values. Tool call indices and IDs must remain consistent across partial deltas; emit a finish reason when the upstream protocol provides one. `provider_metadata` carries bounded JSON state required to round-trip provider-specific tool-call context. | Honor cancellation and timeout. The runtime accumulates provider metadata on the normalized tool call and passes it back to the provider in the next request. The runtime does not expose it in traces or tool arguments. Keep it JSON-compatible and bounded. The runtime retries only before the first text delta and enforces the response cap incrementally. |
| `Retriever` | `async retrieve(query, *, limit, filters)` | Return at most `limit` `Document` values, ordered most relevant first, with stable source attribution and JSON-compatible metadata. | Must not mutate request inputs. The runtime validates count and rendered context bounds after return; extensions must bound their own database work and allocations. |
| `KnowledgeStore` | `retrieve`, `ingest`, `replace_source`, `delete_source` | `ingest` returns the processed count. Source replacement is atomic and returns the new document count; deletion is safe when repeated. | Own storage transactions and connection lifecycle. Keep blocking database and filesystem work off the event loop. |
| `EmbeddingProvider` | `async embed(texts)` | Return exactly one finite, non-empty numeric vector per input, in input order. A provider must use one consistent vector dimension for an index. | Bound batch size, input and output bytes, token length, and execution time. Keep credentials host-managed and require TLS for remote transport. Local inference must stay off the event loop and document model-specific pooling or prompt requirements. |
| `AsymmetricEmbeddingProvider` | `async embed_queries(texts, *, prefix=None)` and `async embed_documents(texts, *, prefix=None)` | Return one consistent finite vector per item, using role-specific task behavior for queries and indexed documents. | `HybridRetriever` and `HybridIndexCoordinator` call the matching role method when present; ordinary `EmbeddingProvider` implementations continue to use `embed`. The embedding evaluator also separates role-specific calls. |
| `VectorStore` | `upsert`, `replace_source`, `delete_source`, `search` | Search returns no more than `limit`, nearest first, with IDs and metadata preserved. Replacement of one source is atomic. Reject incompatible vector dimensions. | Own transactions and resource limits for scans, storage, and result materialization. `GenerationAwareVectorStore` implementations additionally enforce monotonically increasing fencing tokens and idempotent generation cleanup. |
| `Reranker` | `async rerank(query, documents, *, limit)` | Return no more than `limit` documents selected from the candidates, ordered by relevance. Preserve each selected document's identity, source, generation, text, and metadata. | Bound candidate count, outbound request/response size, and timeout. Do not invent or rewrite evidence. |
| `SkillSelector` | `async select(*, task, skills)` | Return `SkillSelection` containing only configured skill identities; dependency expansion and final validation belong to the runtime. | Selection is advisory. Do not grant tools or permissions. Model-backed selectors must honor the agent's request/response byte limits and timeout. |
| `SkillRevocationChecker` | `async check_not_revoked(key_ids)` | Return only when none of the supplied publisher IDs is revoked; raise `SkillRevokedError` for a revoked signer and fail closed on backend errors. | Called before execution and polled during active runs when configured. Shared implementations own their consistency and propagation guarantees; Gabby does not cache decisions. |
| `SkillRevocationStore` | `revoke`, `reinstate`, `revoked_key_ids` plus the checker operation | Persist signer state; `reinstate` reports whether a record was removed and listing returns a `frozenset` of IDs. | Use a durable shared authority when processes run on multiple hosts. Writes must become visible to checks within the deployment's stated propagation bound. Keep listing bounded to the deployment's expected key population. Host owns backend lifecycle. |
| `RedisSkillRevocationStore` | `RedisSkillRevocationStore(async_client, *, key, max_entries, scan_batch_size)` | Implements `SkillRevocationStore` using a host-owned async Redis client's `execute_command`; checks use one `SMISMEMBER` call, and management operations use `SADD`, `SREM`, and bounded `SSCAN`. | Requires Redis 6.2+ and a Redis 6.2+ async client such as `redis.asyncio.Redis`. Gabby does not construct or close the client. Client routing, credentials, TLS, persistence, backups, namespacing, and consistency remain host responsibilities. Backend errors fail closed as `SkillRevocationUnavailable`; malformed IDs/responses and oversized listing results are rejected. |
| `Planner` | `async plan(*, task, context, memory, capabilities)` | Return `PlanningResult` with a bounded `ExecutionPlan`; each step has an instruction and success criterion. | Planning is optional and advisory. The runtime validates the plan and keeps policy, available tools, and execution limits authoritative. |
| `Verifier` | `verify(*, request, output, trace)` | Return `VerificationResult` with boolean `passed`, a method, JSON-compatible details, and optional evidence strings. Sync and async implementations are accepted. | A raised error, invalid return type, or `passed=False` fails enabled verification. Avoid putting secrets or excessive payloads in details because they may be returned in API traces. |
| `ApprovalHandler` | `async approve(request)` | Return an explicit `ApprovalDecision`; missing, invalid, or failed approval denies the tool call. | This is the host's human-approval boundary. Use the authenticated `principal` supplied separately by the API; never infer reviewer identity from model context. Respect request cancellation and deadline. |
| `ApprovalAuditSink` | `async record(request, *, approved)` | Return only after the decision has been durably recorded. | Host-owned extension point for local or shared audit backends. The host owns durability, idempotency, availability, privacy, access controls, and retention. A failed or deadline-exceeded write prevents tool execution; runtime errors are sanitized. |
| `SQLiteApprovalAudit` / `AuditedApprovalHandler` | `async record(request, *, approved)` and `async list_records(limit=...)` | Store and return `ApprovalAuditRecord` values containing invocation metadata and a canonical argument digest, never raw arguments. `AuditedApprovalHandler` accepts any `ApprovalAuditSink`. | Optional stdlib helper; the host owns the path, database permissions, backup, and retention. Writes run in a worker thread and fail closed with sanitized `ApprovalAuditError`. Subject persistence is opt-in. SQLite is a single-host implementation, not a shared backend. |
| `AsyncPostgresExecutor` / `PostgresApprovalAudit` | Async `execute(query, *args)` client and `async record(request, *, approved)` | Insert one bounded, content-minimizing decision row using parameterized SQL; raw tool arguments are never stored. | Optional adapter with no PostgreSQL driver dependency. A host-owned asyncpg-compatible pool and migrated table are required; host owns TLS, credentials, schema migration, pool lifecycle, backups, and retention. Duplicate invocation IDs fail closed. |
| `AsyncPostgresPool` / `PostgresGenerationManifestStore` | Asyncpg-compatible host-owned pool; `GenerationManifestStore` operations | Coordinate fenced per-source leases, staged generations, activation, and retirement in PostgreSQL transactions. | Install the `postgres` extra and apply `sql/postgres_generation_manifest.sql` externally. PostgreSQL server time is authoritative. Host owns pool, TLS, credentials, routing, migration, backups, and consistency. All instances still need shared generation-aware lexical and vector stores. |
| `PostgresKnowledgeStore` | `GenerationAwareRetriever` and `KnowledgeStore` methods over a host-owned asyncpg-compatible pool | Shared PostgreSQL lexical ingestion, atomic source replacement, exact JSONB metadata filtering, bounded full-text retrieval, generation staging, active-generation filtering, and stale-writer fencing. | Install the `postgres` extra and apply `sql/postgres_knowledge.sql` externally. Host owns the pool and schema lifecycle. Multi-instance hybrid indexing also requires a shared generation-aware vector store and `PostgresGenerationManifestStore`. |
| `PostgresVectorStore` | `GenerationAwareVectorStore` methods over a host-owned asyncpg-compatible pool | Shared pgvector cosine search with HNSW iterative filtering, exact JSONB metadata filters, generation staging, active-generation filtering, durable dimensions, and stale-writer fencing. | Install pgvector 0.8.0 or newer on the PostgreSQL server, install Gabby's `postgres` extra, and apply `sql/postgres_vector.sql` externally. Configure `dimensions` to match the embedding model (1–2,000 for HNSW); tune `ef_search` and `max_scan_tuples` for corpus recall and latency. Host owns the pool, extension, schema lifecycle, and index resources. |
| `Authenticator` | `authenticate(request)` | Return a `Principal` with a subject and explicit capability scopes, or reject the request. Sync and async implementations are supported. | Calls are bounded by `authenticator_timeout_seconds`; failure is sanitized as service unavailable. Release resources on cancellation. Scope and tenant mapping remain host configuration. |
| `TokenRevocationChecker` | `async is_revoked(*, issuer, token_id, expires_at)` | Return a boolean for the issuer-scoped token identifier. | The check runs for every authenticated request when configured; timeout and errors fail closed. Keep lookup latency bounded and make revocation state durable/consistent to the level required by the deployment. |
| `Tracer` | `async on_event(*, trace_id, agent_name, event)` | Consume one structured `TraceEvent`; events for one run are delivered in order. | Calls from different runs may interleave. Callbacks are awaited within the remaining run deadline. A timeout or exception disables the tracer for that run, records a sanitized `tracer_error`, and does not fail execution. Treat event contents as sensitive. |
| `StreamJournal` | `get_or_create`, `append`, `finish`, `read_after`, `reap`, and `remove` | `get_or_create` atomically binds a session key to the request fingerprint and principal hash, enforces session capacity and cursor validity, and returns `StreamJournalSnapshot`. Event IDs are contiguous from one; `read_after` returns ordered SSE frames strictly after its cursor plus a completion flag. | Inject with `create_app(stream_journal=...)` or `serve(stream_journal=...)`. The host initializes, closes, and protects injected storage. Implement atomic append with per-session byte bounds, reject writes after finish, expire completed sessions by TTL, and turn abandoned runs into terminal recovery errors after `active_ttl_seconds`. The SQLite path option is same-host only; networked deployments can provide a shared backend. Treat serialized frames as sensitive output data. |
| `AsyncPostgresPool` / `PostgresStreamJournal` | Asyncpg-compatible host-owned pool and the `StreamJournal` operations | Persist bounded sessions and ordered event frames in PostgreSQL; server time drives TTL and abandoned-run recovery, and an advisory transaction lock coordinates the global session cap across replicas. | Install the `postgres` extra and apply the packaged `gabby/sql/postgres_stream_journal.sql` migration externally. Inject `PostgresStreamJournal(pool)` through `create_app(stream_journal=...)` or `serve(stream_journal=...)`. Host owns credentials, TLS, pool lifecycle, migrations, backups, and HA. |
| `EngineAdapter` | `daemon_os`, `image_os`, `pull_image`, `start_container`, `exec`, archive operations, and cleanup | Enforce the supplied `ContainerSpec` and return the engine's container ID, bounded command results, or validated archive data. | Every operation receives a timeout bounded by the run deadline. Cleanup must be idempotent and attempt removal after success, failure, and cancellation. Engine API access is privileged; never expose daemon credentials to the agent. |
| `FileParser` | synchronous `parse(content: bytes)` plus lowercase dotted `extensions` | Return ordered `ParsedPage` values. Optional `metadata` is a mapping of JSON-compatible page fields; page numbers are one-based when present. | Runs in the bounded sync callback pool, but cannot be forcibly stopped once started. The built-in PDF parser has decoded stream caps; custom parsers are trusted in-process code and must bound their CPU and memory or use an external process. File metadata supplied to `FileIngestor` overrides parser metadata; Gabby assigns reserved chunk/page fields afterward. |
| `TextChunker` | synchronous `chunk(text)` | Return deterministic, non-empty chunks in source order; preserve source meaning and avoid silently dropping text. | Runs in the bounded sync callback pool. Bound chunk size and intermediate allocations. |
| `Tool` handler | sync or async callable with declared input and output schemas | Accept validated JSON arguments and return JSON-compatible output satisfying `output_schema`. | Runtime enforces `max_input_bytes` on the UTF-8 JSON argument payload before parsing or invoking any handler, then enforces `max_result_bytes` on serialized output. Tool grants, timeout, policy, and optional approval also apply. Ordinary Python handlers are host-trusted; use a sandboxed executable tool when the action must be isolated. Injected `ToolContext.agent_instance_id` is an opaque process-local identity for delegation cycle detection, not authorization or durable state. Sync callbacks already running at timeout may continue unless they cooperate with `ToolContext.cancellation`. |

The `GenerationManifestStore`, `ActiveGenerationReader`, `SourceKnowledgeWriter`,
`GenerationAwareRetriever`, and `GenerationAwareVectorStore` are specialized knowledge contracts used
by `HybridIndexCoordinator`. Their methods and fencing semantics are documented in the
[extension guide](EXTENSIONS.md) and
[ADR 0012](architecture/adr/0012-durable-hybrid-index-generations.md).

## Shared implementation requirements

- Treat request data, retrieved text, model output, and documents as untrusted. Runtime policy is
  enforced by Gabby and cannot be widened by an extension's response.
- Keep remote calls, database work, and blocking filesystem access off the event loop. Use the
  bounded callback bridge only for synchronous operations that can safely run in a worker thread.
- Apply transport-level caps before reading a full response. Runtime-side result checks happen after
  an extension returns and cannot reverse memory already allocated by that extension.
- Keep credentials in host-managed configuration. Use HTTPS for remote services and avoid putting
  tokens, prompts, or private endpoint details in exception messages, traces, or logs.
- Provider adapters should raise typed errors with sanitized messages. Suppress exception chaining
  from transport and response-parsing failures when the original exception can contain credentials,
  endpoint details, prompt text, or provider response content.
- Treat `timeout_seconds` and cancellation as part of the operation contract. Close sockets, child
  processes, temporary files, and transactions when cancellation arrives.
- Validate extension outputs before using them. Gabby validates model responses, tool schemas,
  retrieval counts/context, skill activations, plans, verification results, and API payloads, but
  extension authors still own their internal resource and data-integrity checks.

## Compatibility policy

This reference documents implemented behavior for the current pre-1.0 release. It does not imply
that every interface is ready to freeze. The proposed v1.0 supported surface and deprecation window
are described in the [compatibility policy](COMPATIBILITY.md); maintainers will confirm the final
set and required contract tests in the v1.0 release notes. A runtime check or structural `Protocol`
match alone is not a promise of behavioral compatibility.
